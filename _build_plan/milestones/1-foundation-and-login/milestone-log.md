# Milestone 1 — Foundation & Login

## What's new in the app

- **A whole new look.** The starfield-and-glass "celestial" theme is gone. The app now looks like a set of cloth-bound Bible volumes on a dark wooden shelf — deep green, gold ("gilt") and cream paper tones throughout.
- **Sign in through a green cloth book cover.** The login screen is now a single book board, front and center, with the app's name stamped in gold and a Google sign-in button printed on a paper slip.
- **A new top navigation bar ("running head").** Every page now shows the same dark header: the app name on the left, three links — Dashboard, Tracker, Profile — on the right, and your avatar at the far right. On phone-sized screens, the bottom tab bar now has all three destinations (it used to only have two).
- **No more light/dark toggle.** The app now has one fixed look, so the sun/moon switch is gone.
- **No more starfield background.** The animated night-sky canvas that used to sit behind every page no longer renders.

## What was built

- **`frontend/src/lib/volumesTokens.ts`** (new) — the shared source of truth for the Volumes design system's JS-side values: `CATEGORY_ORDER`, `CLOTH` (the nine category cloth colours), `ROMAN` numerals, `GILT`, `PAPER_EDGE`. Milestone 1 only consumes `GILT` and `CATEGORY_ORDER` (Dashboard's category breakdown now imports `CATEGORY_ORDER` from here instead of keeping its own duplicate copy), but the rest is populated now so milestones 2-4 have one place to import from instead of re-duplicating it a third time (the prototype files each already duplicate all five).
- **`frontend/src/index.css`** — added a Tailwind v4 `@theme {}` block with the Volumes system tokens (`--color-shelf`, `--color-shelf-lit`, `--color-leaf`, `--color-leaf-rule`, `--color-leaf-red`, `--color-ink`, `--color-gilt`, `--font-slab`, `--font-body`), which gives every later milestone free utilities like `bg-shelf`/`text-gilt`/`font-slab` in addition to the plain `var(--color-*)` CSS variables used throughout this milestone's inline styles. Added browser-surface theming (`::selection`, caret, scrollbar, `:focus-visible`). Removed `@plugin "daisyui"` and the `@variant dark` declaration, and every celestial-only class (`.glass-card`, `.glass-input`, `.section-label`, `.font-cinzel`, `.font-cormorant`, `.serif-note`, the `nebulaDrift1/2/3` keyframes). Added `.slab` (Bevan display type), `.tracker-input` (Tracker's search/chapter-entry field chrome), and `dialog.cycle-dialog` + its `::backdrop` (replaces DaisyUI's `.modal`/`.modal-box` centering and dimming for Profile's confirmation dialog). Kept the chapter-logging animation keyframes (`ring-ripple`, `fade-slide-up`, `chapter-sweep`, `chapter-fill`, `chapter-drain`, `chapter-bloom`) untouched — they aren't celestial-specific.
- **`index.html`** — swapped the Google Fonts link to Archivo + Bevan (dropping Lora, Cinzel, Cormorant Garamond, Raleway); removed the inline theme-flash-prevention script and the `data-theme="light"` DaisyUI attribute; changed `<meta name="theme-color">` to the shelf colour (`#2A231C`).
- **`frontend/src/lib/ThemeContext.tsx`** — deleted outright, per the PRD. `main.tsx` no longer wraps `<App/>` in `ThemeProvider`.
- **`frontend/src/App.tsx`** — unmounted `CelestialBackground` (the component file itself is untouched — deletion is milestone 5's job). Retokenized the PWA update banner, the keyboard-shortcuts FAB button, and the keyboard-shortcuts modal, none of which read `isDark` — they hardcoded dark-celestial rgba directly, so they needed fixing by hand rather than by following the `isDark` grep.
- **`frontend/src/components/PWAInstallModal.tsx`** — same situation as above (fully hardcoded to dark-celestial colours, not `isDark`-gated); retokenized in full.
- **`frontend/src/Login.tsx`** — full rewrite as the "Board" variant from `prototypes/LoginVariants.tsx`: a single green cloth binding face-on, blind-stamped panel, nested gilt fillet, the stacked "Bible / Books / Tracker" title in gilt Bevan, a gilt rule, and the Google sign-in button on a paper "slip." The `GoogleLogin`/`handleSuccess`/`onError`/`useAuth` logic is untouched. The old `CosmicCanvas` starfield (a second, Login-only starfield implementation, separate from `CelestialBackground`) and its ~200-line inline `<style>` block are gone.
- **`frontend/src/components/NavBar.tsx`** — full rewrite as the running head: product name in gilt Bevan on the left, Dashboard/Tracker/Profile as small-caps links on the right (all three are now visible nav links on desktop, not just Dashboard/Tracker with Profile tucked into the avatar dropdown), a gilt rule under the header, avatar at the far right. The mobile bottom bar grew from 2 tabs to 3 (Dashboard/Tracker/Profile) to match. Same props signature and same three call sites (`Dashboard.tsx`, `components/Tracker.tsx`, `Profile.tsx`).
- **`frontend/src/components/UserMenu.tsx`** — dropped the `showProfileLink` prop and the dropdown's "Profile" button; the dropdown is now just "Sign out," since Profile has its own nav link and mobile tab.
- **`frontend/src/Profile.tsx`** — the "Start New Cycle" confirmation `<dialog>` no longer uses DaisyUI's `modal`/`modal-box`/`modal-action`/`modal-backdrop` classes (DaisyUI itself is removed from the project). It uses the native `<dialog>` element directly, styled by the new `dialog.cycle-dialog` CSS in `index.css` for centering and backdrop dimming, with a click-outside-to-close handler replacing the old backdrop `<form>`.
- **`package.json`** — `daisyui` dependency removed (`npm uninstall daisyui`).
- **Retokenizing pass** — every file that branched on `isDark`/`useTheme()` (`ActivityHeatmap`, `ArcProgress`, `BookCard`, `FilterSelect`, `ReadingRhythm`, `SegmentedProgressBar`, `Skeleton`, `Dashboard`, `Profile`, `components/Tracker`, plus `NavBar`/`UserMenu` covered above) had the hook removed and every ternary collapsed to a single fixed Volumes-appropriate value (mostly `rgba(35,31,26,X)` — the Volumes ink colour — replacing the old `rgba(13,21,51,X)` "cosmic navy," and `rgba(210,166,63,X)` — gilt — replacing the old `rgba(100,130,255,X)`/`rgba(150,175,255,X)` blue accents). `ArcProgress` took `isDark` as a prop rather than via context; the prop and its one call site (in `BookCard`) were both dropped. This was a pure detokenizing pass — no layout or composition changes to Dashboard, Tracker, or Profile, per the PRD's explicit scope for this milestone.
- **`frontend/src/components/CelestialBackground.tsx`** — kept (not deleted, per PRD — deletion is milestone 5), but its `useTheme()` calls were replaced with a fixed module-level `theme = 'dark'` constant so it still compiles now that `ThemeContext` is gone. It is unmounted everywhere and inert.
- **`frontend/src/lib/PreviewProvider.tsx`** — an unused dev-preview helper that also imported `ThemeContext`; the `ThemeProvider` wrapper was removed so it still compiles. Nothing imports this file currently.

## Decisions made during implementation

- **Token architecture**: `volumesTokens.ts` (JS-side values — category colours, Roman numerals, gilt/paper-edge hexes) plus a Tailwind v4 `@theme{}` block in `index.css` (CSS-side system tokens). This was locked in during planning, not improvised.
- **Running-head chrome sits on the dark shelf ground**, not paper — confirmed with the user during planning.
- **UserMenu's Profile dropdown link was removed** rather than kept redundantly — confirmed with the user during planning.
- **Google's sign-in button switched from `theme="filled_black"` to `theme="outline"`** so it reads clearly against the cream paper slip — confirmed with the user during planning.
- **Dashboard's local `CATEGORY_ORDER` duplicate was folded into the new shared `volumesTokens.ts`** rather than left as a second copy, since Dashboard was already being touched for retokenizing and the PRD calls out consolidating this exact duplication.

## Anything the next milestone will need to know

- **`frontend/src/lib/volumesTokens.ts`** exports `CATEGORY_ORDER`, `CLOTH`, `ROMAN`, `GILT`, `PAPER_EDGE` — import from here, don't re-copy from the prototypes.
- **`@theme` tokens available**: `--color-shelf`, `--color-shelf-lit`, `--color-leaf`, `--color-leaf-rule`, `--color-leaf-red`, `--color-ink`, `--color-gilt`, `--font-slab`, `--font-body` (usable both as Tailwind utilities like `bg-shelf` and as `var(--color-gilt)` in inline styles).
- **`.slab`** utility class = Bevan display type. Tailwind's built-in `tabular-nums` class covers tabular numerals; no custom class was needed for that.
- **Dashboard, Tracker, and Profile were only detokenized this milestone** — their layouts/compositions are unchanged and still owe their real Volumes redesigns to milestones 2 (Tracker), 3 (Dashboard), and 4 (Profile). Card chrome across all three is currently a plain white/cream card (`rgba(255,255,255,0.88)` background, `rgba(35,31,26,0.12)` border) — a placeholder, not the "opened register leaf" or "contents leaf" treatment those milestones will build.
- **`components/CelestialBackground.tsx` is dead code** (unmounted, unreferenced) but still compiles — milestone 5 deletes it along with `frontend/src/lib/PreviewProvider.tsx`'s now-pointless remaining wrapper (`AuthProvider`/`SyncProvider`/`MemoryRouter` only) if it's still unused by then.
- **`getCategoryPalette` in `frontend/src/lib/categoryColors.ts` is a separate, older category-accent palette** (not the new `CLOTH` tokens) still used by `BookCard`, `Dashboard`, and `components/Tracker` for category glows/accents. It was left untouched this milestone since it isn't `isDark`-gated and isn't celestial-specific — but it's a second category-colour system alongside the new `CLOTH` map, and milestones 2-4 should decide whether to consolidate onto `CLOTH` or keep both for their different purposes (accent glow vs. cloth-swatch colour).
