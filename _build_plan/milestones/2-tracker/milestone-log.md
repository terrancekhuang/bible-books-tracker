# Milestone 2 — Tracker

## What's new in the app

- **The book grid is gone — Tracker is now a shelf of nine volumes.** Each volume is a category (Law, History, Poetry, Major Prophets, Minor Prophets, Gospels, Church History, Paul's Epistles, General Epistles), sized by how many chapters it holds, with a gilt strip along its top edge that fills left-to-right as you read through it.
- **Click a volume to open its contents leaf** — a page of ruled entries, one per book, each with a leader-dot line to its chapter count and a coloured progress rule underneath.
- **Search and a status filter still reach every book at once**, but now they collapse the shelf into a single flattened leaf listing every match across all nine volumes, instead of filtering a grid.
- **Logging is unchanged in substance**: pick a book, type a range or list of chapters, and the same chapter-by-chapter progress bar (with its fill/sweep animation) shows what's about to be logged. Undo, Reset, and Mark all as read all still work, now living at the foot of the leaf.
- **Keyboard navigation is reshaped around the shelf**: `←/→` or `h`/`l` switch which volume is open, `↑/↓` or `j`/`k` move between entries on the open leaf. `/` search, `Tab`/`i` to the chapter field, `Enter`, `u` undo, `R` reset, `A` mark-all, and `Esc` all still work as before. The old `gg`/`G` jump-to-first/last-book shortcuts are gone — there's no long list to jump around in anymore.
- **Coming from the Dashboard still works**: "Continue reading" opens straight to the right volume and book, a category tap opens that volume, and a testament tap flattens the leaf to that testament's books.
- **The Testament, Category and Sort controls are gone.** Category is now expressed by which volume you open, and the four-way sort didn't fit a shelf where each volume lists its books in a fixed order. Search and Status remain.

## What was built

- **`frontend/src/components/VolumeShelf.tsx`** (new) — the row of nine cloth-bound spines standing on a wooden shelf, ported from the approved `frontend/src/prototypes/Volumes.tsx` reference. Each spine's width is proportional to its category's total chapters (`flex: ${total} 1 0`), its head-edge gradient shows read-percentage in gilt vs. raw paper, and the open volume lifts 18px with a brighter cloth tone. Wrapped in `overflow-x: auto` so it scrolls horizontally rather than breaking on phone widths.
- **`frontend/src/components/ContentsLeaf.tsx`** (new) — the open volume's (or a flattened search/filter's) table of contents: laid-paper texture, a red double rule under the heading, and one ruled row per book with dot leaders, a chapters-read count, and a `scaleX` progress rule tinted by that book's own category cloth colour.
- **`frontend/src/components/TrackerEntryLine.tsx`** (new) — the foot-of-leaf chapter-entry mechanic: the bottom-border input and solid "Enter" button from the prototype, the existing `SegmentedProgressBar` (kept — see decisions below) for the selected book, and the Undo / Reset / Mark-all-as-read action row.
- **`frontend/src/components/Tracker.tsx`** — rewritten composition. Replaced the old grid+detail two-panel (with its `isMobile`-driven layout swap) with a single stacked column: status banners → `NavBar` → search/status row → `VolumeShelf` → `ContentsLeaf` → `TrackerEntryLine`. Replaced the 2D-grid `moveSelection` keyboard math with two one-dimensional movers, `moveVolume` (cycles `CATEGORY_ORDER`) and `moveEntry` (cycles whatever book list is currently visible). Page background is the same dark wood-shelf gradient the prototype's `.w-vol` world uses (`repeating-linear-gradient` grain + a `#1D1813`→`--color-shelf`→`#17120E` vertical gradient), since the shelf's spine shading and dimming were designed against a dark ground.
- **`frontend/src/lib/trackerLogic.ts`** — removed `sortBooks`, `SortKey`, `SortDir`, `statusRank`, and the `filterCategory`/`availableFilterOptions` machinery (all now unused — see deviations). Added `defaultBookForCategory(books, category)` (the book a volume opens to: first with unread chapters, else the first book) and `invalidChaptersMessage(bookName, numChapters)` (the new "X has N chapters" hint text). Both are unit-tested in `frontend/src/lib/__tests__/trackerLogic.test.ts`, which also lost its `sortBooks`/`availableFilterOptions` describe blocks and the category-filter cases in `filterBooks`'s.
- **`frontend/src/components/FilterSelect.tsx`** — deleted. It became fully unused once Testament and Category dropdowns were dropped; nothing else in the app referenced it.
- **`frontend/src/App.tsx`** — updated the keyboard-shortcuts help modal: removed the `gg`/`G` rows, split the old single "Navigate books" row into "Switch volume" (`←/→`, `h`/`l`) and "Navigate entries" (`↑/↓`, `k`/`j`).
- **`frontend/src/index.css`** — added `.vol-num` (Archivo, tabular numerals — the prototype's numeral/label utility class, ported verbatim from `prototypes/proto.css`'s `.vol-num`).
- **`frontend/src/prototypes/main.tsx` / `frontend/src/prototypes/Prototypes.tsx`** (new file) — unrelated fix done first: moved the `Prototypes` component out of `main.tsx` into its own file so `react-refresh/only-export-components` stops failing CI. `main.tsx` is now a bare entry point.

## Decisions made during implementation

All confirmed with the user before building:

- **Filters narrowed to Search + Status only.** Testament, Category, and the four-way Sort are dropped entirely — Category is redundant with picking a volume, and Sort didn't fit a shelf where each leaf lists books in a fixed order.
- **Mark all as read is kept**, restyled into the entry line, even though the PRD's bullet list for this milestone didn't call it out by name.
- **`R` (reset) and `A` (mark-all, two-step) keyboard shortcuts are kept** alongside the PRD's rewritten volume/entry navigation.
- **No volume auto-opens on load.** The shelf shows all nine spines with nothing selected until the user picks one — the one-level-up equivalent of today's "select a book to begin" landing state.
- **Opening a volume (by click or by `h`/`l`) auto-selects a book** inside it — the first with unread chapters, or the first book if the whole volume is complete (exactly the prototype's `onSelect` behaviour) — to keep logging fast.
- **`SegmentedProgressBar` (the granular per-chapter view, with its sweep/fill/bloom animations) is kept**, shown under the entry line for the selected book, alongside the leaf's simpler per-row progress rule. Dropping it would have lost real, recently-shipped functionality nothing in the PRD asked to remove.
- **Search/status flattening**: a non-empty search or an active status filter replaces the open volume's leaf with one flat leaf listing every match across all nine categories, in the same canonical order `/api/books` already returns (`book_id ASC`). Clearing both restores whichever volume was open before.
- **Dashboard's two Tracker deep-links are reinterpreted, not dropped**: a `filterCategory` link now opens that volume (`openVolume`); a `filterTestament` link sets an internal, dropdown-less `testamentFilter` that flattens the leaf to that testament's books — the same flattening path search/status already use. No changes were needed in `Dashboard.tsx` itself.
- **Mobile**: the shelf/leaf stack is single-column by nature, so the old `isMobile` grid/detail split and its "← Back" mobile-only affordance are gone. The shelf scrolls horizontally below a floor width; the "← Back" link (for Dashboard's `selectBook` deep-link) now shows on any width whenever `openedFromNav` is true. This is a functional, not fully polished, mobile pass — milestone 5 owns the dedicated phone-width pass.
- **A selection that falls outside the currently visible leaf clears itself.** Typing a search or picking a status can flatten the leaf out from under whatever book was selected; an effect drops the stale selection the moment it's no longer in `visibleBooks`, rather than leaving the entry line pointed at a book no longer shown above it. This wasn't pre-specified — it surfaced during manual testing.

## Anything the next milestone will need to know

- **`frontend/src/lib/volumesTokens.ts`'s `CATEGORY_ORDER`, `CLOTH`, `ROMAN`, `GILT`, `PAPER_EDGE`** are now consumed for real (Tracker was the first page to actually use them beyond Dashboard's `CATEGORY_ORDER` import from milestone 1).
- **The dark shelf background** (`repeating-linear-gradient(91deg, rgba(0,0,0,0.16) 0 2px, transparent 2px 9px), linear-gradient(180deg, #1D1813 0%, var(--color-shelf) 44%, #17120E 100%)`) lives as a local `SHELF_BACKGROUND` constant in `Tracker.tsx`, not in `index.css` — it's Tracker-specific since Dashboard and Profile aren't shelf-themed. If Profile or Dashboard ever want the same wood-grain ground, promote it to a shared utility instead of re-copying.
- **`getCategoryPalette` (`frontend/src/lib/categoryColors.ts`) is untouched** and still powers `BookCard`/Dashboard's category glow accents — it's a separate colour system from the new `CLOTH` map, same as milestone 1 left it. Milestone 3/4 still owe a decision on whether to consolidate.
- **`chapters_read_list` is assumed sorted/deduped** by the backend (unchanged assumption from before) — `defaultBookForCategory` and the leaf's progress rules rely on `chapters_read`/`num_chapters` counts, not the list itself, so this doesn't add any new coupling.
- **Undo is now available even on a fully-read book** (previously the complete-book state only offered Reset). This is a minor, additive behavior change noticed during manual testing — nothing in the PRD required either way, and it's consistent with "Undo the last entry… acting on the selected entry" not being conditioned on completeness.
- **The `run-bible-books-tracker` skill's Playwright driver mocks books with a stale category taxonomy** (`"Epistles"`, `"Prophecy"` instead of the real `"Paul's Epistles"` / `"General Epistles"` / `"Church History"`) that doesn't match `CATEGORY_ORDER`. This wasn't fixed here (out of scope — it's the skill's fixture, not app code) but it means the skill's own screenshots will show 2-3 volumes as empty/unfilled until its mock data is updated to the real nine-category schema.

## Deviations from the PRD

- **Testament, Category, and Sort controls are removed**, not just left alone — the PRD's own "what gets built" bullet only mentions "search and the status filter," but didn't explicitly say to drop the others. Confirmed with the user during planning; `FilterSelect.tsx` was deleted as a result since it became fully unused.
- **`SegmentedProgressBar` retained** alongside the leaf's per-row progress rule — an addition beyond the PRD's literal bullet list, kept to avoid regressing real existing functionality (see decisions above).
- **Undo is now offered on complete books**, a small behavioral broadening from before (see above) — not requested, not prohibited, done to keep Undo consistently available wherever Reset is.
