Bible Books Tracker — Volumes Redesign

Rebuild every screen of Bible Books Tracker in the Volumes visual world — the Bible as a nine-volume set in publisher's cloth, one volume per category, each opening to a ruled contents leaf. The celestial/glassmorphism identity is retired entirely across Login, Dashboard, Tracker and Profile. Every existing capability is preserved; only the visual world and each page's arrangement change.

This is a frontend-only project. No endpoint, table, or column changes: every number these pages show is already returned by the existing API. The work runs on the branch ui-redesign across five milestones, each ending in a state you can open in a browser and use.

The approved visual reference lives in the repo: frontend/src/prototypes/Volumes.tsx for the shelf and contents leaf, and frontend/src/prototypes/LoginVariants.tsx (the board variant) for Login. Both render at /prototypes.html in dev. They are the design contract for this work.

What the redesign delivers

  • The Volumes design system

    Nine cloth colours keyed to category, gilt and raw-paper edges, blind stamping, a laid-paper leaf with red rules, a dark shelf ground. Bevan for titles, Archivo for everything else.

  • Login — the front board

    A single green cloth binding seen face-on, gilt fillet and stacked title, with Google sign-in printed on a paper slip laid against the board.

  • Dashboard — the record leaf

    An opened register page: the day at the head, the year's reading as a pricked calendar, streak and weekly goal as marginalia, where to continue below.

  • Tracker — shelf into leaf

    Nine volumes standing on a shelf; open one to its contents leaf and log chapters there. Search and status filter cut across all sixty-six books so nothing is far away.

  • Profile — gilt medallions

    Lifetime stats, reading rhythm and cycle history, with achievements as tooled roundels — gold when earned, blind when not. The emoji badges are gone.

  • Running-head navigation

    A printed running head across the top of every page — product name left, the three destinations as small caps right, a rule under, avatar at the far right. Chrome that recedes.

  • One committed theme

    The light/dark toggle is removed, not restyled. ThemeContext is deleted and all thirteen components that branch on isDark move to fixed Volumes tokens.

  • Retiring the celestial system

    The starfield canvas, nebula and glass CSS, the Cinzel/Cormorant/Raleway stack, DaisyUI and the prototypes folder all come out once nothing references them.

Already provided by the existing codebase

None of this needs to be re-specced or rebuilt. The redesign consumes it as-is.

  • Google OAuth sign-in and JWT session handling
  • Every API endpoint the pages need
  • All four database tables and the seed data
  • TanStack Query data layer and cache persistence
  • IndexedDB offline write queue and replay
  • PWA install and Workbox caching
  • Eight logic test suites (no render tests to break)
  • CI lint / build / test and deploy on master
  • The approved Volumes and Login prototypes
  • The drawn SVG icon set in Icons.tsx

Out of scope

  • Backend or database changes — every number these pages show is already returned by an existing endpoint.
  • New product capabilities — no reading plans, notes, verse-level tracking, sharing or social. This is a redesign, not a feature release.
  • Reworking offline or PWA behaviour — the write queue and caching strategy are untouched; only the sync banner's appearance changes.
  • A new icon set — the existing SVGs are already one consistent stroke weight; they get recoloured, not redrawn.
  • Self-hosting or licensing fonts — Bevan and Archivo load from Google Fonts, as in the prototype.
  • A guided onboarding tour — empty and first-run states are in scope; a walkthrough is not.
  • Photography or illustration assets — the world is built from CSS materials, so there is nothing to source or commission.
  • Renaming the product or changing auth — still Bible Books Tracker, still Google sign-in.

Milestones

1

Foundation & Login

Establishes the visual system every later milestone draws from, replaces navigation, removes the two systems that fight the new world, and rebuilds Login. This is the largest and riskiest milestone because removing the theme system touches every component.

What gets built

  • One Volumes token set: nine category cloth colours, gilt, raw paper edge, leaf paper, red rules, shelf ground, ink
  • Bevan and Archivo loaded; Cinzel, Cormorant Garamond and Raleway dropped from the font load
  • Browser surfaces themed: text selection, caret, focus ring, scrollbar, tabular numerals
  • The running head on every page, with a bottom bar on mobile
  • Theme toggle removed and all thirteen isDark components moved to fixed tokens
  • DaisyUI plugin and dependency removed; Profile's dialog restyled without it
  • The starfield stops rendering — the celestial component is unmounted app-wide
  • Login as the green cloth board: blind-stamped panel, gilt fillet, the stacked title, a gilt rule, and Google sign-in on a paper slip — no strapline, no counts, no verse

Not in this milestone

  • The Dashboard, Tracker and Profile compositions — they keep their current arrangement, just on new tokens
  • Deleting the celestial files and CSS — that is milestone 5
  • Deleting the prototypes folder — later milestones still reference it
  • The new keyboard scheme

Done when: You can sign in through the green board and land on a fully working app with the running head at the top, no theme toggle anywhere, no starfield or glass card rendering, and no console errors.

2

Tracker

The shelf becomes the logging surface. This is the page the product lives or dies on, so logging speed matters more here than anywhere else.

What gets built

  • Nine volumes on a shelf; thickness shows how many chapters a volume holds, the gilt head edge shows how far into it you have read
  • Opening a volume reveals its contents leaf: laid paper, red double rule, one ruled entry per book with leader dots, a chapters-read count, and a progress rule in that volume's cloth colour
  • Search and the status filter cut across all sixty-six books into a single flat leaf, so no book is ever more than one action away
  • A chapter entry line at the foot of the leaf that accepts ranges and lists, tells you how many are new, and refuses out-of-range input with a message naming the book's real chapter count
  • Undo the last entry and reset a book, both acting on the selected entry
  • Keyboard: left/right or h/l between volumes, up/down or j/k between entries, / to search, Tab or i to the field, Enter to submit, u to undo, Esc to clear, ? for help, and the g-h / g-t / g-p page chords
  • The help modal updated to the new scheme, with gg and G removed
  • Empty states: a volume with nothing read yet, and a search that matches nothing
  • The pending-sync banner in the leaf's own material

Not in this milestone

  • Dashboard and Profile
  • Filters or sorts beyond the ones that exist today
  • Any change to how offline writes are queued or replayed
  • Per-chapter selection or a chapter-level grid

Done when: You can open any volume, log a range of chapters into a book, watch that entry's rule and the volume's head edge both move, undo it, and reach any of the sixty-six books by search — all without touching the mouse.

3

Dashboard

The Dashboard becomes an opened register leaf — the page bound into the back of a family Bible where the reading gets written down. It deliberately does not lead with the shelf, so it never reads as the same page as Tracker.

What gets built

  • The record leaf: the day's date at the head, an engraved heading, red double rule
  • Overall progress shown as a small closed set, with chapters read against 1,189 and books complete against 66
  • Current streak, chapters today, and the weekly goal as marginalia, with the goal editable in place
  • A year of activity as a pricked calendar in gilt on the leaf, with a readable tooltip on both pointer and touch
  • Continue reading: the most recent in-progress books as ruled entries that jump into the Tracker
  • Testament and category breakdown as ruled entries with cloth-colour progress rules
  • Loading skeletons drawn in the leaf's own material rather than grey blocks
  • A first-run state for a user who has logged nothing at all

Not in this milestone

  • The volume shelf — that is Tracker's signature and stays there
  • Reading rhythm charts — those belong to Profile
  • Logging chapters from the Dashboard
  • Any statistic the existing endpoints do not already return

Done when: The Dashboard loads in one request and shows the day, the streak, an editable weekly goal, a year of activity and where to continue — all on the leaf, with no glass card anywhere and every figure matching what the Tracker shows.

4

Profile

The owner's page — everything about the reader rather than the reading. This is where the emoji achievement badges finally die.

What gets built

  • Identity: name, email and avatar, presented as a bookplate inside the cover
  • Lifetime figures: best streak, total chapters, reading days, average pace
  • Achievements as gilt medallions — tooled roundels, gold when earned and blind-stamped when not, with the criteria readable in both states so an unearned one still tells you what to do
  • Reading rhythm by weekday and by part of day, across both the all-time and last-90-days windows the API returns
  • Cycle history: past cycles as earlier sets, each with its own aggregate figures
  • Start a new cycle, behind a confirmation dialog built in the world's own vocabulary rather than DaisyUI's
  • The weekly goal control, consistent with the Dashboard's
  • Empty states for a reader with no achievements and no prior cycles

Not in this milestone

  • New achievements or changes to how existing ones are earned
  • New rhythm windows or breakdowns
  • Editing name, email or avatar — those come from Google
  • Deleting a cycle or exporting data

Done when: Profile shows every figure it shows today, achievements read as gilt-and-blind medallions with no emoji anywhere on the page, and starting a new cycle works end to end through the redesigned dialog.

5

Retire & polish

Delete the old world now that nothing renders it, finish the states the page-level milestones did not cover, and make the whole thing hold up on a phone.

What gets built

  • The celestial background component, all nebula and glass CSS, and the old font definitions deleted outright
  • The theme context file deleted and the stored theme preference cleared
  • The prototypes folder and its entry page removed
  • PWA install prompt, sync indicator, error states and the not-found page in the Volumes vocabulary
  • The installed app's theme and background colours updated away from the old indigo
  • A full pass at phone width across all four pages
  • A contrast check on every text and background pairing in the new palette
  • The project's own documentation updated to describe the Volumes world instead of the celestial one

Not in this milestone

  • New features of any kind
  • Backend or deployment changes
  • New test suites
  • Revisiting locked design decisions from earlier milestones

Done when: Lint, build and the full test suite all pass, searching the codebase for the celestial system returns nothing, and all four pages hold up at both phone and desktop width.
